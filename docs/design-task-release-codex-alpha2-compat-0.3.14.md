# 0.3.14 发布说明

## 概要

正式版 `0.3.14` 修复插件在 DSH `0.2.1-alpha.2` 上的登录端点静默失效问题，并把支持的宿主版本扩展到该版本，同时保留 `0.2.0-rc.2` 与 `0.2.1-alpha.1`。发布渠道为 GitHub Release，不发布 npm；本次不自动安装或重启现有 DSH。

## 修复内容

- `0.2.1-alpha.2` 移除了 `webRuntime` 服务。Cordis 会在任一注入依赖缺失时让该注册保持不激活，因此旧的 `ctx.inject(['webServer', 'webRuntime'])` 会让登录端点在 `0.2.1-alpha.2` 上**静默消失**：不报错、不崩溃，只是设置页不再出现登录卡片。现收敛为只注入稳定的 `webServer`。
- 信任来源改为按请求读取现存服务，两代来源累加：`webRuntime`（`0.2.0-rc.2`／`0.2.1-alpha.1`）与 `webStartup`（`0.2.1-alpha.2`）。新宿主独立接受监听地址本身，因此该绑定字面量也纳入判断；缺少它会让绑定到 LAN 地址的部署拒绝自己的浏览器。
- 通配绑定（`0.0.0.0`、`::` 及其映射形式）不作为任何地址的授权；能力令牌、跨站来源与 DNS rebinding 检查不变。
- `peerDependencies` 增加 `0.2.1-alpha.2`；开发依赖与类型核对基线升级到该版本。

## 安装与升级

从 [v0.3.14 GitHub Release](<https://github.com/tanuki-cat/dsh-codex/releases/tag/v0.3.14>) 下载安装包，在下载目录执行：

```sh
dsh plugin --profile web add ./dsh-llm-chatgpt-0.3.14.tgz
```

安装前备份 profile 配置；安装后重启承载插件的原 DSH Web 进程并刷新页面。只刷新浏览器不会更新服务端插件。

从 `0.3.13` 升级不需要额外迁移：本版本不新增 profile 配置项，也不改变凭据、模型目录或额度行为。

## 验证与限制

发布前执行 `npm run check`、`npm run build`：

- 无 `DSH_INSTALL_ROOT` 的单元测试：180 项中 169 项通过、0 失败、11 项跳过（缺少已安装宿主）。
- 真实已安装 DSH `0.2.1-alpha.1`：180 项中 179 项通过、0 失败、1 项跳过。
- 真实已安装 DSH `0.2.1-alpha.2`：180 项中 179 项通过、0 失败、1 项跳过。
- 以 `DSH_PACK_TEST=1` 单独执行[打包配置测试](<../tests/packed-codex-config.test.ts>)：1 项通过、0 失败、0 跳过。

修复本身做过反向验证：在真实 `0.2.1-alpha.2` 上以旧的 `['webServer', 'webRuntime']` 注入，端点不注册；改为 `['webServer']` 后注册成功。构建产物的信任栅栏另以 10 项用例核对两代来源、绑定字面量与各类拒绝路径。

宿主集成测试原先按 `0.2.1-alpha.1` 固定假设编写，本次改为按安装版本自适应：工具呈现模式 `both` 在该版本被移除、原生模型目录已包含 `gpt-6.1-sol`、文件工具套件新增 `workingDirectory` 依赖、`ptc` 模式下只有 `run_code` 可直呼。这些是该次测试适配，不是插件行为变更。

未验证真实浏览器登录、真实账号模型推理、跨平台 GUI 及其它未声明宿主版本。不承诺此版本修复真实图片端点故障。
