## 检查与凭据刷新

- 检查要求已声明 `openai-codex` 路由、可写模型设置和已存 OAuth access token；过期状态仍显示检查入口。
- 已知到期时间不足五分钟且存在 refresh token 时，尝试宿主刷新器。刷新还依赖兼容的公开 API、可写 DSH 凭据存储及网络可用。
- 刷新提交后重新读取 access token 和账号身份，再请求目录；不另实现令牌交换，不向页面返回令牌。失败时提示重试或重新登录，不继续写模型补丁。
- 预览不写模型配置，但可能刷新 OAuth 凭据；“只读预览”不能理解为凭据存储绝不变化。宿主 API 不兼容时保留已有凭据，过期令牌需重新登录。

## 目录同步与恢复

重复检查会保留显式模型配置和运行时已有模型，追加新安装 pi-ai 的原生 ID 及远端可安全表达的缺失模型。仍需预览并确认，不能把目录快照理解为自动 overlay。

恢复流程是“检查恢复原生目录 → 查看受影响条目 → 确认恢复原生目录”：

1. 读取当前安装的原生目录，列出将恢复默认能力的显式条目和将不再可选的非原生模型；此时不写配置。
2. 单独确认后，在相同 revision 条件下将 `providers.openai-codex.models` 设为空列表。空列表使宿主采用原生目录，也避免继承层的非空列表继续接管目录。
3. 重查原生 ID 集合，确认后显示恢复结果；其它路由设置不变。

**恢复不是撤销上一次补丁**：它清空全部显式模型条目，包括用户自定义的模型能力配置，而不是仅删除最近新增的 ID。用户需先检查预览；未保存恢复前显式配置的完整备份时，不承诺一键恢复这些自定义值。恢复不依赖 OAuth 或远端目录可用，但需要兼容的原生目录 API 和可写模型设置。

## 确认与能力边界

写入使用预览签名与 `expectedRevision`。仅目录遍历顺序变化不冲突；显式配置顺序变化仍视为用户修改。注册确认最多读取五次，等待间隔为 100、250、500、1000 毫秒，只重查状态，不重复写入或自动撤销。

目录元数据可以支持生成补丁；模型 ID 已注册可以支持“已补充模型”。二者都不能证明真实推理成功，也不能证明旧版 pi-ai 已支持新协议、图片、传输方式或全部推理等级。未支持等级及继承的输出上限在预览中明示。

## 请求版本

`client_version` 的优先级为：

1. `DSH_CODEX_CLIENT_VERSION`，必须为合法版本号；无效值使检查失败，不静默忽略。
2. `codex --version`，探测有 1.5 秒超时及输出大小限制。
3. 内置 `0.160.1`。

实际选择结果在同一补丁服务实例内复用并随预览展示。升级 CLI 或修改进程环境后应重启 DSH；这不改变来源能力必须验证的要求。
