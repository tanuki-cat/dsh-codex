# Codex 图片生成工具实施方案

## 状态与概要

状态：首版代码已实现，真实 GUI 验收待执行（2026-10-09）。实现与自动化证据见[实施记录](#实施记录)；图片端点尚未通过真实账号实测。

在现有 `dsh-llm-chatgpt` 插件内注册 `image_gen` 工具，复用 ChatGPT 登录凭据，直接调用 Codex 独立图片接口，并通过 DSH 附件服务展示和下载图片。用户已确认现有登录凭据可以调用普通模型；图片端点权限和额度通过首次图片调用单独验收。

不调用外部 Codex CLI、不修改 pi-ai 聊天协议、不新增 OAuth、不要求 `OPENAI_API_KEY`，不自动回退到另行计费的 API。

## 已核对事实

- 当前插件版本为 `0.3.11`，见[包配置](<../package.json>)；登录、模型补丁和用量服务由[插件入口](<../src/index.ts>)挂载。
- 本机 Codex CLI 版本为 `0.162.0`。核对同版本官方源码，图片扩展通过独立 ImagesClient 请求，不依赖聊天 Responses 的原生图片工具事件。
- Codex 使用 `gpt-image-2`，质量与尺寸默认均为 `auto`，见[官方工具实现](<https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/ext/image-generation/src/tool.rs>)。
- 独立接口为 `images/generations` 和 `images/edits`，见[ImagesClient](<https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/codex-api/src/endpoint/images.rs>)。
- ChatGPT 登录默认基址为 `https://chatgpt.com/backend-api/codex`，见[Provider 实现](<https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/model-provider-info/src/lib.rs>)；图片后端复用当前 Provider 鉴权，见[图片后端](<https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/ext/image-generation/src/backend.rs>)和[Bearer 请求头](<https://github.com/openai/codex/blob/rust-v0.162.0/codex-rs/model-provider/src/bearer_auth_provider.rs>)。
- 当前插件已有宿主 pi-ai 凭据刷新事务，见[认证绑定](<../src/host-catalog.ts#L47-L74>)；不需要另存一份 Token。
- 已安装宿主的 `read_image` 实现使用 `tools.register(defineTool(...))`、`attachments.saveImage(...)` 和图片附件内容块，可作为注册和输出实现依据；实施时需要核对宿主公开导出及类型。
- 已检查的宿主文件服务提供文本写入，没有二进制写入接口。不能据此假设存在 `writeBytes`，或用 Node 文件操作绕过沙箱。

## 首版范围

首版支持：

- 根据提示词生成单张图片。
- 透明背景。
- DSH 会话图片展示及现有附件下载能力。
- 刷新页面和恢复会话后查看持久化图片。
- 登录过期、权限不足、额度不足、取消、超时及保存失败处理。

首版不支持批量生成、任意图片模型选择、专用图片管理页面、任意目标路径写入或精确尺寸保证。

第二阶段增加编辑能力：使用明确指定的本地参考图片，通过宿主文件服务读取，调用 `images/edits`，输出新图片，不覆盖输入图片。暂不引入“最近 N 张图片”语义，避免跨工具或会话选错图片。参考图片上传到远端的行为必须在工具契约中明确。

## 调用链路与请求

```text
用户提出图片需求
  → 模型通过 run_code 调用 tools.image_gen(...)
  → 检查附件服务、输入和凭据
  → 必要时通过宿主 pi-ai 刷新凭据
  → POST Codex images/generations
  → 有界读取、校验并解码图片
  → 保存到 DSH 附件服务
  → 返回图片附件和简短元数据
```

计划请求：

```http
POST https://chatgpt.com/backend-api/codex/images/generations
Authorization: Bearer <access>
ChatGPT-Account-ID: <accountId>
Content-Type: application/json
```

```json
{
  "model": "gpt-image-2",
  "prompt": "...",
  "background": "opaque",
  "quality": "auto",
  "size": "auto"
}
```

透明背景使用 `background: "transparent"`。请求发送到固定可信端点，禁止重定向，不允许模型传入 URL 或 Token。按官方实现核对 `originator`、`x-codex-image-turn-id` 等附加请求头后接入；不得将猜测的头字段当作已验证要求。

上述内容描述拟接入协议，不是已执行成功的 DSH 请求。

## 工具契约

工具名：`image_gen`。名称与当前 imagegen 技能的发现规则一致。

| 参数 | 规则 |
| --- | --- |
| `prompt` | 必填非空字符串，描述画面、用途及约束；实施时设定长度上限。 |
| `transparent_background` | 可选布尔值，默认 `false`。 |

描述明确用于生成位图，不替代适合 SVG、HTML/CSS 等代码原生资产的任务。参数默认值和约束只写在对应参数定义中。

成功返回图片附件引用、实际宽高、格式、字节数、实际图片模型，以及可用的请求标识。不返回 Token 或 Base64 文本。图片通过 DSH 标准图片内容块返回，不使用 Codex 专属的 `generatedImage()`。

核对原生和 `run_code` 嵌套调用输出，确保两者都能显示图片。向 DSH 提供宿主适配指引，明确 `image_gen` 调用方式、附件保存语义和失败处理；不修改用户的全局 imagegen 技能，不承诺 Codex 的默认保存目录。

不修改现有模型目录来伪造图片生成能力。首版在工具调用时检查有效 ChatGPT 凭据；工具可见性不等于账号有权调用图片端点。当前会话模型无法接收图片内容时，应在出站前明确拒绝，除非已验证宿主支持仅向用户展示附件的独立结果路径。

## 凭据与生命周期

- 复用现有 `CODEX_KEY`，读取 `access`、`accountId`、`expires` 和刷新所需字段。
- 请求前确保足够有效期，复用[现有认证绑定](<../src/host-catalog.ts#L47-L74>)及 DSH 凭据事务，避免与普通模型刷新竞争。
- 刷新后重新读取账号和 Token；注销或账号变化时，不继续使用旧身份发起请求或向新身份返回旧结果。
- 复用机制若需要更长有效期或调用者取消信号，仅做必要参数化，不另实现 OAuth。
- 首版同一插件实例内按账号串行执行图片请求；不把不同提示词合并为一个请求，不声称跨进程全局串行。
- 排队等待可取消，插件卸载停止在途请求并清理监听器。
- 建议远端请求期限为 180 秒；实施前核对宿主工具调用、run_code 和后台作业超时机制，避免宿主提前终止。
- 取消本地请求不保证远端生成停止或额度退回，错误文案必须说明结果不确定性。
- 不新增 Web 生成端点，不向浏览器传输 Token。

## 图片保存与展示

发送生成请求前检查附件服务是否可用、允许的格式及容量限制。收到响应后：

1. 有界读取 JSON，限制响应总字节数及解码后的图片大小。
2. 校验 `data`、`b64_json`、图片格式和返回数量；不得静默丢弃异常的额外图片。
3. 使用宿主附件服务检查尺寸、格式并持久化。
4. 返回附件引用及图片内容块，复用现有 GUI 的展示和下载路径。

不将 Base64 塞入普通工具文本、日志或自建 HTTP URL。不将任意工作区写入权限视为插件可以直接写文件的授权。

首版不提供任意项目导出路径。实施时核对附件归一化、透明通道和原始字节保留能力：若服务进行缩放或重编码，要明确下载文件语义，不承诺原始分辨率。原始输出保留及工作区导出另行设计，不扩大本次范围。

远端生成成功但附件保存失败时报告保存阶段失败，不自动重新生成；是否能安全保留可恢复结果，取决于已验证的宿主存储能力。

## 错误与重试

| 情况 | 计划行为 |
| --- | --- |
| 无凭据或字段不完整 | 发请求前拒绝，提示登录或修复配置。 |
| 明确的鉴权拒绝 | 核对可刷新条件后最多刷新并重试一次；刷新失败停止。 |
| 403 | 提示图片端点权限不足，不声称普通模型不可用。 |
| 429 | 区分可识别的额度不足和限流，遵守 `Retry-After`，不自动生成重试。 |
| 网络中断、超时、5xx | 不自动重发；提示远端可能已生成、可能消耗额度。 |
| 空返回、异常 JSON/Base64、损坏图片 | 返回有界、脱敏错误，停止处理。 |
| 本地附件保存失败 | 明确远端成功、本地保存失败，禁止自动再次生成。 |
| 用户取消、插件卸载 | 停止等待和后续处理，不报告已成功。 |

不以普通模型的 5 小时或周额度推算图片额度。不自动回退到独立 OpenAI API 或其他图片模型。

诊断保留脱敏阶段、状态码及请求标识，不记录提示词、图片内容、access、refresh 或账号标识。上游原始错误需要过滤，不能直接展示或写入日志。

## 代码组织

首版模块：

| 模块 | 职责 |
| --- | --- |
| `src/image-api.ts` | 固定端点请求、响应限制与校验、错误分类。 |
| `src/image-service.ts` | 凭据准备、取消、并发控制和附件保存。 |
| `src/image-tool.ts` | 工具注册、参数、结果 schema 和展示定义。 |

在[插件入口](<../src/index.ts>)注入工具与附件服务，在[上下文类型](<../src/types.ts>)补充必要接口。保持当前可选服务惯例：缺少工具或附件服务不影响原有登录、用量查询和模型补丁。

使用宿主公开 API，并核对需要补充的 peerDependencies；不导入宿主私有 bundle 文件、不安装第二份 pi-ai。卸载注入作用域时释放工具注册和对应任务。复用认证代码仅作必要提取，不扩大重构。

## 实施步骤与验收

### 阶段一：注册与附件 smoke

- 核对宿主公开工具、附件接口和调用者模型能力。
- 使用假响应注册工具，验证模型工具列表和 run_code SDK 能发现 `image_gen`。
- 验证原生与嵌套调用的图片结果、持久化和下载。

### 阶段二：真实生成闭环

- 实现独立图片请求、凭据准备和透明背景。
- 接入取消、超时、账号变化、并发和错误分类。
- 验证调用者信号到网络及保存阶段的传播。

### 阶段三：自动化验证

新增独立替身测试及真实宿主集成测试，覆盖：

- 固定 URL、鉴权头、模型与默认参数；透明背景映射。
- 无凭据、临近过期、刷新竞争、刷新后账号变化。
- 401 有界重试；403/429/5xx/超时不产生自动重复生成。
- 不同提示词不合并、排队取消、插件卸载和资源清理。
- 超大或畸形响应、异常 Base64、损坏图片及意外多图返回。
- 附件保存失败、能力缺失、图片内容块和敏感信息不泄漏。
- 插件卸载后工具消失；原有登录、模型补丁和用量查询不受影响。

沿用[项目脚本](<../package.json#L40-L44>)，计划执行 `npm run check`、`npm run build`、受影响的 Node 测试及 `git diff --check`。真实宿主集成使用现有 installed 测试惯例；不得把未设置宿主路径而跳过的测试报告为已通过。测试选择需覆盖所有实际改动，不机械执行整仓测试。

### 阶段四：真实 GUI 验收

经用户授权执行有限次数的真实生成，记录请求次数和结果，不用真实生成填充自动化测试：

1. 用户直接提出生成需求，模型调用 `image_gen`，不运行 Shell 或 Python。
2. 生成普通图片和透明背景图片各一张，核对显示、实际尺寸、下载和透明通道。
3. 刷新页面并恢复会话，附件仍可访问。
4. 核对取消、超时、额度或权限失败提示，不自动追加生成请求。
5. 回归普通模型调用、登录和用量查询。

安装后重启原 DSH Web 进程，在既有 `http://127.0.0.1:3080` 验收，不另起替代服务。部署、真实生成和发布不属于本次文档写入操作。

首版通过标准：用户直接说“生成一张图”，模型无需 Shell、Python 或额外登录即可调用工具，图片在 DSH 中可持久查看、可下载；错误不会引起无界重试或重复消耗。

### 阶段五：图片编辑

首版验收后，增加明确本地参考图片路径、最多五张输入的限制、沙箱读取、出站上传说明和非破坏性输出。以同版本官方请求类型核对编辑 JSON，不套用另一路 OpenAI API 的 multipart 假设。

## 待验证项

- DSH 当前 OAuth 凭据是否被图片端点接受，以及账号图片权限、额度和错误返回。普通模型已验证，不重复排查普通模型登录。
- 固定端点对附加请求头、超时和返回格式的实际要求；该端点属于 Codex 后端，不能承诺公共稳定 API 兼容性。

## 实施记录

### 首版实现（2026-10-09）

- [图片 API](<../src/image-api.ts>)固定请求 Codex Images 端点，设置 `originator: dsh-llm-chatgpt` 与随机 `x-codex-image-turn-id`，读取官方 `x-codex-imagegen-request-id`。禁止重定向；JSON 流、Base64 和解码后的图片均有大小限制，只接受一张 PNG/JPEG/WebP。
- [图片服务](<../src/image-service.ts>)复用 `CODEX_KEY` 和[宿主认证事务](<../src/host-catalog.ts>)，提供实例内按账号排队、可取消等待、凭据更新观察和卸载清理。服务期限为 180 秒，包含排队、刷新、网络及保存等待；图片输入上限还受宿主附件限制约束。
- 401 后只对被拒绝的 access token 进行临时到期投影，交给 pi-ai 在共享事务中刷新；投影不落盘，不要求新令牌拥有超过旧令牌的有效期。已被其它请求刷新后的令牌不会因旧 401 再次旋转。
- [工具注册](<../src/image-tool.ts>)使用公开 `defineTool`，声明 210 秒工具预算；嵌套调用需显式提供至少 240 秒的 `run_code` 预算。未修改模型目录或全局 imagegen 技能。
- 标准图片内容块引用宿主持久化附件。真实附件服务测试确认透明通道保留以及序列化引用可由新服务实例读取；保存结果可能经过缩放和重编码，不承诺原始字节。
- 宿主 `saveImage` 没有取消参数：取消或卸载会等待已开始的保存结束，再拒绝返回成功；取消后可能留下未引用附件。未新增临时 Base64 缓存或恢复导出接口。
- 可选 tools、attachments、llm 注入作用域独立于 Web 服务。新增宿主包为可选 peer，开发类型和本机集成核对版本为 `0.2.1-alpha.1`；没有把旧宿主版本当作图片工具兼容性证据。
