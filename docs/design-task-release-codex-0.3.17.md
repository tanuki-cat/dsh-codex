# 0.3.17 发布说明

## 概要

正式版 `0.3.17` 把声明的宿主版本补到 DSH `0.2.2-rc.3`，并回填 `0.2.1-alpha.3` 至 `0.2.1-alpha.5`、`0.2.1-rc.5`、`0.2.2-alpha.3`、`0.2.2-rc.1` 与 `0.2.2-rc.2`。这些版本此前没有任何 peer 条目覆盖，宿主按运行中版本比对全部 `@deepseek-ai/dsh*` peer 时会把插件判为不兼容并要求逐版本豁免。

插件生产代码无需改动：登录端点注入、工具注册、命令与客户端贡献在这几代宿主上行为一致。变更集中在版本声明、开发与类型核对基线，以及两处只影响测试的适配。

## 兼容声明

- 五个 peer 条目统一补上 `0.2.1-alpha.3`、`0.2.1-alpha.4`、`0.2.1-alpha.5`、`0.2.1-rc.5`、`0.2.2-alpha.3`、`0.2.2-rc.1`、`0.2.2-rc.2` 与 `0.2.2-rc.3`；[安装脚本](../scripts/install-local.ts)直接读清单中的范围，[对应测试](<../tests/install-local.test.ts>)的接受版本列表同步。
- 开发依赖与类型核对基线升级到 `0.2.2-rc.3`。该代的 `@deepseek-ai/*` 包把 `@deepseek-ai/cordis` 的 peer 从 `~4.0.6-alpha.1` 提到 `~4.1.0`，与 `0.2.2-alpha.2` 的包不能共存于同一棵 npm 树，因此必须整体换基线而不是逐个升级。
- 声明的宿主范围因此是 `0.2.1-alpha.1` 至 `0.2.2-rc.3` 的连续代际。`0.2.0-rc.2` 仍只出现在授权与凭据两个包里，宿主自身的兼容检查以工具类包的范围拒绝它。

## 宿主变化与插件行为

- **客户端模块来源**：插件声明在 `dsh.manifest.client.inject` 里的模块由宿主的模块加载器按 id 提供。`0.2.2-rc.2` 起 Chat、设置页等客户端 bundle 改由安装目录内的模块 id 注册（`0.2.2-rc.2` 为 90 个、`0.2.2-rc.3` 为 91 个，此前这类 bundle 直接以包路径解析），插件自己的客户端产物仍只 `require` `react` 与 `@deepseek-ai/dsh-client-ui-primitives`，因此无需改动；[客户端测试](<../tests/client.test.ts>)在这几代上均通过。
- **工具呈现与批量调用**：`0.2.2-alpha.2` 引入的执行器插件与 `calls` 批量契约在 `0.2.2-rc.3` 保持不变，[宿主集成测试](../tests/helpers.ts)的按代分支无需新增条件。
- **客户端打包形式**：`0.2.2-rc.2` 起 Chat 客户端 bundle 被压缩，工厂函数末尾的 `return module.exports;` 去掉空格写作 `return module.exports`。插件运行时不依赖该文本，只有[原生折叠展示测试](<../tests/installed-init-presentation.test.ts>)用它在私有 VM 中插入观测出口，改用同时接受两种写法的正则。

## 安装与升级

从 [v0.3.17 GitHub Release](<https://github.com/tanuki-cat/dsh-codex/releases/tag/v0.3.17>) 下载安装包，在下载目录执行：

```sh
dsh plugin --profile web add ./dsh-llm-chatgpt-0.3.17.tgz
```

安装前备份 profile 配置；安装后重启承载插件的原 DSH Web 进程并刷新页面。只刷新浏览器不会更新服务端插件。

从 `0.3.16` 升级不需要额外迁移：本版本不新增 profile 配置项，也不改变凭据、模型目录、额度或命令接口的字段。已安装 `0.2.2-alpha.2` 的机器无需更换宿主，本版本同时保留该代声明。

## 验证与限制

发布前执行 `npm run check`、`npm run build` 与完整测试：

- 单测（`DSH_INSTALL_ROOT` 未设置）：185 项中 174 项通过、0 失败、11 项跳过（缺少已安装宿主）。
- 宿主集成：在临时目录中逐代真实安装 `@deepseek-ai/dsh` 后以 `DSH_INSTALL_ROOT` 指向，对 `0.2.1-alpha.1` 至 `0.2.2-rc.3` 的 15 个代际各跑一次全量，全部 0 失败。`0.2.1-alpha.1` 至 `0.2.1-alpha.3` 为 184 项通过、1 项跳过，其余各代为 183 项通过、2 项跳过。跳过的两项是 11 项宿主集成中按约定单独运行的打包测试，以及 `0.2.1-alpha.4` 起不再提供可加载 `dsh-client-ui-slots` 模块的 SlotCore 注册表测试（`0.2.1-alpha.4` 至 `0.2.1-alpha.5`、`0.2.1-rc.1` 之后各代均如此；`0.2.1-alpha.1` 至 `0.2.1-alpha.3` 仍可加载，因此少跳过一项）。
- 以 `DSH_PACK_TEST=1` 单独执行[打包配置测试](<../tests/packed-codex-config.test.ts>)：1 项通过、0 失败、0 跳过。
- 真实 `dsh plugin` 安装：在隔离的 `DSH_HOME` 下各建一个 `web` profile，`0.3.17` 在 `0.2.2-rc.3` 上安装成功；同一宿主上用 `0.3.16` 会被判为不满足 requirements 并回滚，说明本版本声明确实解除了该拒绝。

未验证真实浏览器登录、真实账号模型推理、真实图片端点、跨平台 GUI 及其它未声明宿主版本。自动化通过不代替真实 GUI 验收。
